## 一句话定义

同一个操作执行一次和执行多次，对系统状态的影响相同，这个操作就是幂等的。

注意约束的是**系统状态**，不是返回值。删除一个不存在的资源返回 404，但状态没变，仍然算幂等。

## 为什么不幂等是个问题

网络世界里「没收到响应」和「请求没到达」无法区分：

```
客户端 ──请求──▶ 服务端
客户端 ◀─超时──  服务端（其实已经执行成功）
客户端 ──重试──▶ 服务端   ← 第二次执行
```

没有幂等约束时，第二次执行就会产生第二份副作用：多扣一次款、多发一条消息。

## 常见的三类实现手段

| 手段 | 适用场景 | 代价 |
|---|---|---|
| 天然幂等 | 赋值、覆盖写 | 无 |
| 唯一键约束 | 落库去重 | 需要可靠的去重键 |
| 状态机 + 前置条件 | 有明确状态流转的业务 | 需要状态设计 |

## 边界在哪里

幂等只覆盖重试，不覆盖**并发**。两个并发的同 key 请求同时到达时，
唯一键约束仍然是最后一道防线；而状态机方案必须依赖原子比较并交换（CAS）才能成立。
