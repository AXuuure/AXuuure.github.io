## 为什么要分层

把记忆放进一个池子里，最先出现的两个问题一定会来：
**检索到的内容互相矛盾**，以及**写入的东西越长越脏**。
分层的本质是给不同性质的记忆划出不同的生命周期与写入纪律。

```
┌────────────────────────────────────────────┐
│ 工作记忆   当前任务状态   ── 任务结束即丢弃   │
├────────────────────────────────────────────┤
│ 情景记忆   某次交互的经过 ── 按时间归档、可过期 │
├────────────────────────────────────────────┤
│ 语义记忆   稳定的结论/偏好 ── 长期保留、需确认  │
└────────────────────────────────────────────┘
```

## 写入纪律

1. **工作记忆**：随流程自动写入，不落库，任务结束即回收；
2. **情景记忆**：按会话批量归档，保留原文以供回溯；
3. **语义记忆**：只在明确确认后写入，且必须记下来源与时间戳，允许被后续证据推翻。

## 读取顺序

先用工作记忆回答，命中不了再查语义记忆，最后才回落到情景记忆做补充。
顺序反过来会造成两个后果：上下文被历史对话淹没，且旧结论压过当前任务事实。

## 落地时的三个检查点

- 每条记忆能否回答「谁在什么时候因为什么写下了它」；
- 记忆冲突时，是否有明确的优先级规则而不是靠检索分数；
- 删除一条记忆后，系统行为是否会变回未记住之前的样子。
